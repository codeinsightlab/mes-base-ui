# B1/B2 独立验收脚本

这组脚本只用于验收，不属于生产功能。结果、缺陷和环境证据保存在被Git忽略的本地目录，不追加到公共开发指南。脚本不创建角色、不连接数据库，不代替正式业务准备、目标核实、范围备份或数据库只读核对。

## B1 正式页面故障壳

在确认当前用户服务、版本、身份及指定测试库后，将 `b1-recovery-harness.html` 复制到自有忽略目录 `public/b1b2-qa.local/index.html`，通过现有 Vite 的 `/b1b2-qa.local/index.html` 打开。不要替换现有页面、代理或配置。页面内嵌原 `/production/productionReporting`，按普通流程定位并提交；仅使用独立 QA 对象。

- `normal` 保留真实 Fetch；`lose-body` 仍向正式 API 发送原请求，记录实际返回流水，再向页面提供无法完成的响应体，验证未知结果。它是浏览器故障注入，不是物理网络丢包。
- `403/404/409` 在当前标签页返回明确标记的合成错误，不向后端发送该次请求；原请求必须由生产页面自己保存，不能手填。
- 存储故障只让当前内嵌窗口的恢复 key 对应 getItem/setItem/removeItem 抛异常，不改写或清空原记录。只读证据按钮限定 `userId=100`、`TEST_DEV_PERF_20261019`。
- 数量上下文故障只返回合成503；恢复入口应仍可用。
- 原生表单按钮调用原页面 `form.report-form.requestSubmit()`，用于独立验证 submit 事件；它不是普通用户的确认按钮。
- 正式业务登录凭证仍只走原服务；壳不记录请求头或 Token，不向探针传输真实身份。
- 记录中的 `kind=report-post` 才是报工尝试；`recovery-read-only` 只是只读取证。真实后端发送还须排除 `injected=true`。

结束后恢复故障开关，按正式原 UUID 恢复流程核实未决请求；不得为清理验收环境删除恢复记录或不可变事实。关闭自有验收标签页；已有用户标签页及浏览器存储保持原样。

## B2 本机无数据库探针

从仓库根运行：

```sh
python3 scripts/acceptance/b1b2/b2-probe.py
```

脚本仅监听 `127.0.0.1:18763`。启动时从现有 Vite 的 `/src/lib/request.ts` 读取真实编译模块，移除内联 source map，保存 SHA256；创建自有临时证据目录并输出地址和自身PID。无需安装依赖、修改配置或重启用户服务。若端口已占用应先核实，不能停止不属于本脚本的进程。

在真实浏览器打开输出地址，点击“执行响应生命周期验收”。17项结果保存为临时目录中的 `results.json`，请求路径和时间保存为 `network.jsonl`。只有合成 `synthetic-a/b` 身份会发送到探针；不要用真实 Token 替换。测试使用1秒截止时间并允许浏览器调度抖动，记录实际耗时；发送650ms加读取650ms用于区分共享截止时间与重新计时。成功SSE先发送有效 `data:` 事件帧，持续超过普通截止时间后由调用方取消。

测试后在自身终端会话发送 Ctrl-C，只停止该探针，并核对退出及端口无监听。不要停止5173/8081用户服务。保存结果与截图到自有忽略目录，勿提交完整业务数据或凭证。该探针证明请求库的真实浏览器传输行为，不能证明 B1 的账号、权限或正式报工恢复。
